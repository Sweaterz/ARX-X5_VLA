## 修改

Server 元数据新增 `recommended_actions_per_chunk` 和来源说明：训练 dataset repo_id 为 `local/fold_box_v1_pi05` 时使用最多 50 帧，其他模型沿用 8 帧。GUI 与命令行客户端使用该值，并检查不超过服务声明的预测长度。

不放大、不跳过、不重排预测动作，不修改 SDK 限位或默认平滑。总步数设置仍生效，暂停、人工接管和急停仍逐帧检查，旧代次不能继续发送。

推理返回前仍要求观测/推理耗时不超过既有 1.5 秒。返回后的动作属于未来轨迹，按 30 Hz 的单调时钟时间表顺序发送；每帧调度迟到超过 250 ms 时停止并保持，不补发积压动作。原先把整条轨迹统一限定在观测后的 1.5 秒，会在 50 帧执行完前误判过期；现在区分推理延迟与未来动作的计划执行时间。SDK 反馈与原有故障保护不变。

这些证据解释了旧客户端的执行停滞，但不证明 checkpoint 已学会完成折盒任务。真机路径与任务成功率仍须现场验证。
