# 命令行 Ctrl+C 更新（2026-09-16）

仅适用于 start_client.sh run --robot sdk --cameras realsense --enable-motion：初始化完成后，Ctrl+C 请求停止任务，在下一次检查处丢弃后续模型动作，捕获实际姿态并进入 JOINT 位置保持。完成指定步数同样进入保持。进程继续运行并检查反馈故障和看门狗。

保持期间再次 Ctrl+C 只显示提示，不释放控制。放稳/支撑双臂后，输入大写 EXIT 并回车才请求保护、关闭 SDK。终端输入关闭、SIGHUP/SIGTERM、SDK 故障或超时仍走退出保护，不能保证支撑。同步推理/相机/SDK 调用尚未返回时暂停可能延迟，不能替代硬件急停；看门狗已触发时不会强行恢复保持。

GUI 服务 Ctrl+C、官方示例和独立 pause_mode_demo.py 的退出行为均未改变。仅新启动的 CLI 进程生效。本次 37 项离线测试通过，未做真机测试。

# 暂停与后台保持（2026-09-13 最新规则）

本节替代下文旧版“页面失联即保护”的说明。

- 正常完成 VLA 或点击“暂停并保持”：反馈正常时捕获当前位置交给 SDK 保持，不自动续跑。
- 关闭页面或心跳丢失超过 2 秒：结束当前任务，反馈正常时转后台保持。后台服务必须持续运行；再次打开页面须点击“接管后台保持”，不会恢复旧任务。
- 急停、SDK 故障、看门狗超时、反馈异常或保持失败：请求保护，不强行保持；软件无法保证即时停机。
- 断开设备：确认已放稳/支撑双臂后释放 SDK，不再保持。退出服务也会释放控制。
- 红色“软件紧急停止”仍请求保护，与“暂停并保持”不同。

## 操作顺序

1. server 在 zhhy@192.168.2.117 上另行启动：`cd ~/projects/kai0 && ./local_scripts/start_arx_lerobot_server.sh --port 8000`。
2. 停止其他运动 client。若采集服务还占着设备，双臂保护且录制空闲时点“释放采集服务占用”；状态无法核实会拒绝停止服务。
3. 点“连接机械臂”，确认双臂有支撑、周围无遮挡。调用已有 SDKRobot 初始化、互斥锁和保护，不自动归位。
4. 点“连接相机”，查看三路图像。相机占用会显示错误。
5. 先点“无运动测试”：用真实状态和图像推理一次、检查完整动作块、记录预测和越界；不调用运动 command。连接 SDK 本身仍会初始化硬件并请求保护。
6. 需要时切换“重力补偿”或“保护模式”。归位、测试、VLA 运动只在保护模式下开始。
7. “双臂归位”调用 SDK go_home(duration=8, wait=False, gripper=False)，不是自行插值；目标为 SDK 零位，夹爪不归位。等待至少请求时长和连续反馈到位，20 秒未到位请求保护。路径没有碰撞检测，执行前确认整条路径。
8. “开始 VLA 运动”需确认，最多执行所填 1–300 步；原始动作交给 SDK 限位与轨迹平滑；客户端保留故障、有限值和超时检查。服务器必须显式返回 checkpoint、14 维、test_only=false、motion_enabled=true。
9. 结束后“断开机械臂”，释放相机和控制锁。停止锁定时，该按钮变为“断开并解除停止锁定”，然后再显式连接。

## 软件停止与限制

红色“软件紧急停止”无需确认，立即设置停止标志；工作线程检查后请求 SDK 保护，停止状态锁定，不自动续跑。按钮固定在页面顶部。页面心跳超过 2 秒失联也请求保护并断开。SDKRobot 原有 2 秒看门狗保留；VLA 推理过程中不会通过反馈读取给该看门狗续期。

这些都是软件保护，不保证即时停机。阻塞的 SDK 调用、线程锁、进程/系统故障可能延迟或阻止保护；遇到危险必须用硬件急停。保护失败会记录错误。没有碰撞检测、物理路径验证或急停认证。正式硬件归位/重力/模型运动尚未通过本页面验证。

Idle 模式成功读取反馈后会维护 SDKRobot 看门狗；浏览器心跳、SDK fault 和反馈检查仍生效。模式操作使用 SDK；不修改 ARX5_beta 文件，不绕过底层保护，不自动重启其他服务。

日志：`logs/gui-*.jsonl`，包含完整预测、越界维度/数值/限位/差值和操作记录。界面只展示最近事件，完整内容看文件。
