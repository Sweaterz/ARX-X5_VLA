# ARX 双臂拖动式 DAgger

实现位置：`/home/qijun/Documents/zhanghaoyi/kai0_arx_client`。GUI 仍使用 8092，左侧新增「DAgger 采集」。不修改官方 SDK，不启动 ROS2 主从入口，不启动微调。

## 操作

1. 控制台启动 Server，待绿灯就绪；连接机械臂、完成归位或暂停并保持，再连接相机。
2. 切到 DAgger，输入任务与每轮策略步数，点击「开始试验并录制」。任务与 checkpoint 固定到本次 episode。
3. 扶稳双臂后点击「人工接管」。等待界面明确显示「人工纠正」，再拖动双臂与夹爪。
4. 「结束纠正并保持」进入 JOINT 保持，不自动恢复策略。需要继续时明确点击「恢复 VLA」。
5. 「结束试验并保存」先保持，再排空缓冲、校验 HDF5/视频，完成后显示已保存。结果默认未完成。
6. 可同步回看三路视频。重负载导出、恢复、回收必须先断开机械臂；断开前先归位或支撑双臂。

切页不重新初始化设备。页面失联停止策略并保持，暂停采样；重新接管控制权后可继续原 episode。Server 关闭先暂停并确认保持，保留未结束 episode。急停、反馈故障及模式切换失败走现有 SDK 保护。

## 控制与线程

- GUI Manager 是唯一控制者。接管增加推理代次，旧请求和动作块失效；接管请求与每次动作下发在同一锁内排序。
- 双臂保持确认后调用现有 SDK `gravity_compensation()`；任一侧失败/异常均保护，只有双侧成功才进入人工段。
- 纠正结束调用既有 `hold_current()`，捕获一次包含夹爪的反馈目标。之后 `maintain_hold()` 仅维护反馈/看门狗，保留稳定的 SDK 控制方式。
- 相机采用 spawn 独立进程连续采集；共享内存提供 RGB 图像和时间索引，预览请求不决定采样频率。
- 录制使用独立 `.venv-data` 工作进程；控制线程只验证/拷贝并非阻塞入队，不编码、不写数据文件。原有 GUI 诊断日志机制保留。
- 采样目标 30 Hz，记录实际单调时钟时间；离线按时间重采样，不把循环调度当成硬实时。
- 反馈读取时间最大 50ms、图像最大100ms、三相机最大时差50ms；不合格拒收并暂停保持。RealSense 设备时间转换为主机 monotonic，保留原设备时间和接收时间；这不是硬件同步保证，现场仍需验证时序与负载。当前 SDK 的位置接口没有暴露每电机接收时间戳，反馈50ms检查针对主机成功读取时刻，不能证明 CAN 缓存本身小于50ms；电机故障检测继续依赖官方 SDK。

## 数据

`../datasets/dagger/episodes/<episode>/`：

- `trajectory.h5`：实际采样/反馈时间、14维 qpos、原始策略 action、下发请求、request_valid、intervention、segment、control_mode、三路相机时间和帧序号。
- `head.mp4`、`left.mp4`、`right.mp4`：RGB 编码的三路视频。
- `manifest.json`：任务、checkpoint 配置 SHA256、URDF SHA256、SDK 运动配置、来源、结果、控制事件与原始预测动作块。

人工段没有指令：requested_action/policy_action 为 NaN，request_valid=0，不能解释为专家指令。control_mode 0=JOINT、1=GRAVITY。完整试验包括策略段和人工段；暂停及模式切换不产生训练样本。

写入先位于 `incomplete/`，FIFO 保存屏障后关闭视频并检查帧数与时序，原子移动到 `episodes/`。有界8消息队列满会拒收并暂停，不静默丢帧。磁盘不足1GiB、编码异常或进程退出保留未完成目录。

恢复只保留可解码的共同完整前缀，保留恢复前原文件；强杀导致 MP4 或 HDF5 无法解码时拒绝宣称恢复成功。回收移入 `trash/`，不永久删除。空 episode 可保存元数据，不产生视频。

## LeRobot 导出

默认只导出人工段，各连续段独立 episode，策略/暂停/切换之间不拼接。30Hz 时间网格插值，action=下一帧绝对反馈（约+33ms），移除无未来目标末帧。保留14维顺序、SDK弧度、AC one负夹爪反馈；图像为 head/left/right。不二值化夹爪，不用 action 覆盖 state。

输出位于 `exports/`。实际调用 LeRobot0.6.1 创建与加载，校验50×14动作块、每段末尾49个 padding，以及本机 PI05 checkpoint 的预处理器（CPU，不加载模型权重）。验证成功后写 `dagger_export.json` 并原子提交目录。失败保留 `.incomplete`，不显示已验证。

原训练集时间对齐尚未核实，因此导出通过不能证明可直接混入原数据训练。

## 保存路径设置与页面布局

DAgger 页右侧「保存路径与数据设置」默认折叠。点击「选择文件夹」，在 qijun 电脑的文件夹浏览器中进入目标目录，再点击「使用此文件夹」，后续原始数据位于其 episodes/，训练导出位于 exports/。必须结束录制/保存/数据任务并断开机械臂后修改；修改会校验写入权限并持久保存到 client/dagger_settings.json。不会搬移旧数据，记录列表随当前根目录切换；切回旧目录即可查看旧记录。演示模式显式设置 ARX_DAGGER_DATA_ROOT 时不覆盖正式环境的持久设置。

观察区采用主视角左侧、另两路右侧排列，点击可切换主视角。关节反馈、任务参数和保存设置折叠，接管/保持/结束保存优先显示。

原始 episode 并非 LeRobot 数据集。点击导出后，当前 LeRobot0.6.1 生成 meta/info.json 中 codebase_version=v3.0 的数据集。合并应使用官方数据工具处理索引和元数据，不能直接拼目录；需要一致的 features、FPS、关节单位/顺序、夹爪编码及 state/action 时间定义。当前已验证数据加载和预处理，未进行训练或证明可直接与原训练集混用。

## 三种导出方式与片段裁剪

在试验记录点击「选择导出」，或在回看区点击「读取片段」。读取/导出沿用断开机械臂后执行的限制。

- **仅人工纠正段**：默认选择所有人工段，可以继续排除其中的错误部分。
- **完整有效轨迹**：选择策略与人工采样段，可取消整段或排除局部帧范围。有效指采样质量通过，并不代表模型动作正确，仍需人工回看。
- **指定片段**：自行勾选需要的策略或人工段。

「定位回看」跳到该片段视频起点并自动播放。顶部视频统一控制三路播放/暂停/进度，两个腕部视频仅跟随，避免 seek 事件互相回写；另有「播放三路视频」「暂停回看」按钮。「排除错误／保持画面」可直接填写源帧号，也可用当前视频位置设置起止点。范围从0编号、包含两端，支持多个范围以及撤销。选择只作用于本次导出，原始HDF5、视频和事件不删除。刷新页面后需重新选择，最终选择会随成功导出写入 dagger_export.json。

暂停/保持阶段原本不采样，因此这些事件自动不进入训练数据。导出面板默认关闭「自动去除 human 开头静止帧」：每个人工段用最初3帧机械臂关节中位数作为基线，任一机械臂关节位移达到0.008rad并连续3帧后认定真正开始拖动；夹爪不参与判断。开启选项后，起点之前的帧只从本次 LeRobot 导出中排除；没有检测到机械臂拖动的 human 段整段不导出，包括仅夹爪运动。默认关闭以保留这类有效示教，也可用帧范围手动排除。原始HDF5、三路视频和事件始终不修改；阈值、逐段检测结果和最终排除范围写入 `dagger_export.json`。

三种模式都使用30Hz重采样后的下一帧反馈作为绝对位置目标（+33ms），保留 intervention=0/1。每个控制段、时间断点及排除区间两侧独立生成 LeRobot episode，不跨边界产生目标或50步动作块。剩余不足3个原始帧的片段不导出；没有可用片段时报错。导出清单保存原始帧范围、标签、输出episode索引、排除范围和动作定义，支持追溯。

LeRobot H.264 导出关闭B帧，避免极短片段拼接时出现DTS乱序；官方SDK及LeRobot安装均未修改。

导出按钮上方显示当前保存根目录下的 exports/ 位置，每次导出自动生成独立子目录；成功后显示本次完整目录。文件夹选择器支持返回上一级、主目录、Documents、移动磁盘与挂载目录快捷入口，不读取或上传文件内容。
