# Replay 动作回放

在 `http://192.168.2.136:8092/#replay` 使用。保存成功的 DAgger 记录旁也有“动作回放”入口。无需 Server、相机或 LeRobot 导出。

1. 选择记录，点“加载轨迹（不运动）”。仅读取 saved episode 的 HDF5。
2. 在控制台连接机械臂并归位或进入位置保持。
3. 选择连续片段；点“前往起点”，确认双臂及夹爪的路径。使用 SDK 默认轨迹，到达后等待。
4. 选择 0.25、0.5（默认）或 1 倍速，明确点击“开始回放”。回放使用完整片段，与 VLA 的 300 steps 无关。
5. 片段末尾保留 SDK 最后目标保持。暂停、接管、采样间隙处不自动跨段；下段须明确继续，起点不匹配时先前往起点。

回放源是 14 维实际反馈 qpos，不是模型原始预测，也不是 LeRobot 下一帧监督动作；策略和人工片段均可选择。夹爪负角度保留。按照实际采样时间安排发送，速度倍率仅缩放回放时间，不改变前往起点的 SDK 默认轨迹速度。SDK 限位和默认平滑可能使实际执行与录制轨迹不同。

加载检查维度、有限值、单调时间、标签、型号、单位、CAN 左右顺序和 URDF 校验值，真机拒绝 demo 数据。起点容差为关节 0.05 rad、夹爪 0.15 rad；这是起点一致性校验，不替代 SDK 限位或场景路径检查。SDK 目标无法到达时超时暂停，不能报告已完成。

所有 SDK 操作沿用 Manager 控制线程。读取数据用独立进程和现有 I/O lane，等待期间反馈监测继续。调度延迟超过 200 ms 停止任务，不突发补发欠下的指令。正常暂停和页面失联捕获一次当前位置后保持；任务结束保留 SDK 原目标，无反馈追踪重发。急停和反馈故障沿用已有保护。共享控制权、心跳与任务锁，不能和 DAgger/VLA 同时运动；关闭窗口不等于关闭后台。

原始数据不修改。无硬件验证包含 test_replay.py、既有回归测试和 gui/qa-motion-replay.mjs（仅 --demo 后端）。现场回放仍需确认场景和物体位置；本次实现未执行真机运动。
